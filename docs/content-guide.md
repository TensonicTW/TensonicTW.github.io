# 內容撰寫規範

## 分工

| 內容型別 | 目的 | 誰寫 | 節奏 |
| --- | --- | --- | --- |
| 產品頁 `products/` | 規格的唯一真實來源 | 產品部 | 隨機種異動 |
| 新品發表 `launches/` | 對外宣告，一機一篇 | 產品部 + 行銷 | 依上市時程 |
| 技術分享 `posts/` | 現場做法與設計說明 | 工程、業務工程師 | 每月一至二篇 |

## 寫法

發表文的第一段直接講這台機器解決什麼問題，不要從產業趨勢起手。重點條列以可驗證的數據為主，形容詞留給型錄。

技術分享寫成可複製的流程：問題條件、量測數據、處理方式、預防建議。附上量測儀器與條件，否則數據無法被檢驗。

規格一律以產品頁為準。發表文引用規格時只挑支撐論點的那幾項，其餘連到產品頁，避免兩處數據不同步。

## 雙語

`zh/` 與 `en/` 使用相同 slug。英文版不是逐句翻譯，可依對象調整段落長度，但型號、數據、單位必須一致。單位採 SI，功率寫 `W`，阻抗寫 `Ω`，兩者與數字間留半形空格。

## 命名

- slug 使用小寫與連字號，發表文可加日期前綴：`2026-08-ts-dmp8`。
- 圖片：`public/media/<slug>-<用途>.webp`，寬度建議 1600px 以內。
- 型號在正文中一律大寫並保留連字號：`TS-DMP8`。

## 發佈前檢查

- 規格無「待補 / TBC」殘留。
- 中英文成對存在。
- 外部連結可開啟。
- `npm run build` 無警告。
